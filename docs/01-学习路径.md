# 01 - 8 周学习路径

> 每天 2-3 小时，周末集中做项目。点击每周可查看每日安排和验收标准。

## 整体节奏

- **工作日**：学概念 + 写小练习（每天 2-3 小时）
- **周末**：集中做项目（每天至少 4 小时）
- **项目是主线**：所有概念学习都服务于当周的项目产出

---

## 第 1 周：LLM 基础与 Prompt 工程

**目标**：理解大模型工作原理，能熟练调用 API 并写出高质量 Prompt

| 日期 | 主题 | 内容 |
|------|------|------|
| 周一 | Transformer 核心原理 | 自注意力机制、位置编码、Encoder/Decoder 区别、Tokenization（BPE/SentencePiece）、上下文窗口与 KV Cache 概念 |
| 周二 | 采样参数与模型选型 | temperature、top_p、top_k、frequency_penalty 的作用与调参直觉；主流模型对比（GPT-4o / Claude / 国内模型）的能力边界与价格 |
| 周三 | Prompt Engineering（上） | 零样本/少样本提示、角色设定、指令结构、思维链(CoT)、自洽性(Self-Consistency)、树状思维(ToT) |
| 周四 | Prompt Engineering（下） | 结构化输出（JSON/Function Calling 格式）、Few-shot 示例设计原则、Prompt 防注入、复杂任务的 Prompt 模板工程 |
| 周五 | LLM API 实战 | OpenAI/Anthropic/国内模型 API 调用、流式输出(SSE) 处理、多轮对话历史管理、速率限制与指数退避重试、Token 计数与成本估算 |
| 周末 | **项目：CLI 智能助手** | 实现一个支持多轮对话、流式输出、系统 Prompt 可配置的命令行聊天机器人；加入对话历史自动摘要压缩功能 |

**✅ 验收标准**：能解释 attention 计算过程；能独立调用任意大模型 API 并处理流式响应；写出的 Prompt 能稳定输出结构化 JSON

---

## 第 2 周：Agent 核心概念与手写实现

**目标**：理解 Agent 本质，从零实现 ReAct 循环，不依赖框架

| 日期 | 主题 | 内容 |
|------|------|------|
| 周一 | Agent 架构范式 | 感知-规划-行动循环；ReAct（推理+行动交替）论文精读；Reflexion（自我反思）；Plan-and-Execute；各范式适用场景对比 |
| 周二 | Function Calling 深度 | 工具定义 Schema 规范、参数类型与必填项、工具选择逻辑、并行工具调用、工具执行结果注入对话、工具调用的错误处理与重试 |
| 周三 | 记忆系统设计 | 短期记忆（滑动窗口/摘要压缩）、长期记忆（向量存储/知识图谱）、记忆的写入与检索策略、Episodic vs Semantic 记忆、记忆遗忘机制 |
| 周四 | 规划与任务分解 | 任务拆解策略（自上而下/自下而上）、子目标依赖管理、执行中动态重规划、失败回退与备选路径、最大迭代次数与死循环防护 |
| 周五 | 从零写 ReAct Agent | 不使用任何框架，纯 Python + LLM API 实现：Prompt 模板 → 解析 Thought/Action/Action Input → 执行工具 → 观察结果 → 循环直到 Final Answer |
| 周末 | **项目：多功能 ReAct Agent** | 为手写 Agent 接入 3+ 工具（搜索、计算器、Python 代码执行）；解决至少一个需要 5 步以上推理的复杂任务；加入最大步数限制和错误恢复 |

**✅ 验收标准**：能手写完整 ReAct 循环代码；能设计工具 Schema 并处理调用失败；能解释 Agent 与普通 Chatbot 的本质区别

> ⚠️ **关键提醒**：本周是整个路径的基石。如果手写 ReAct 没搞懂，后面学框架只会是调 API 的熟练工。

## 第 3 周：LangGraph 框架精通

**目标**：掌握最主流的 Agent 框架，能用状态机构建复杂工作流

| 日期 | 主题 | 内容 |
|------|------|------|
| 周一 | LangChain 基础 | LLM/ChatModel 抽象、PromptTemplate、OutputParser、Chain 组合、Message 类型体系（System/Human/AI/Tool/Function） |
| 周二 | LangGraph 核心概念 | StateGraph 状态机、State 定义与 reducer、节点(Node)与边(Edge)、条件边(Conditional Branch)、图的编译与执行 |
| 周三 | LangGraph 高级特性 | 检查点(Checkpointer)持久化、人机交互节点(Interrupt)、时间旅行(Travel)回溯、子图(Subgraph)嵌套、流式输出（节点级/Token级） |
| 周四 | 用 LangGraph 重构 Agent | 把第 2 周手写的 ReAct Agent 用 LangGraph 重写；对比手写版与框架版的优劣；理解框架帮你处理了哪些边界情况 |
| 周五 | 复杂工作流实战 | 实现 Plan-and-Execute 模式：规划节点生成任务列表 → 执行节点逐个完成 → 评审节点检查结果 → 不合格则重规划；加入人工确认节点 |
| 周末 | **项目：研究助理 Agent** | 用 LangGraph 构建：接收研究问题 → 自动拆解子问题 → 调用搜索工具收集资料 → 整合生成报告 → 支持中途人工干预和修改方向 |

**✅ 验收标准**：能独立用 LangGraph 构建多节点、有条件分支、支持持久化的 Agent 工作流；理解 State reducer 的作用；能实现人机交互节点

---

## 第 4 周：RAG 检索增强生成

**目标**：掌握生产级 RAG 全流程，能搭建高质量知识库问答系统

| 日期 | 主题 | 内容 |
|------|------|------|
| 周一 | 文档处理与切分 | 文档解析（PDF/HTML/Markdown）、切分策略（固定长度/语义/递归/结构化）、切分粒度对效果的影响、元数据标注与过滤 |
| 周二 | Embedding 与向量数据库 | Embedding 模型选型与维度、向量数据库对比（Milvus/Qdrant/Chroma/pgvector）、索引类型（HNSW/IVF）、相似度计算（余弦/点积） |
| 周三 | 检索策略优化 | 混合检索（向量+关键词 BM25）、查询改写（HyDE/多查询/步骤回退）、父文档检索(Parent Document)、上下文压缩(Contextual Compression) |
| 周四 | 重排序与生成优化 | Rerank 模型（Cohere/bge-reranker）、检索结果去重与多样性、Prompt 中上下文组织、引用溯源、不知道就拒答的策略 |
| 周五 | RAG 评估方法 | 检索质量评估（Recall@K/MRR/NDCG）、生成质量评估（忠实度/相关性）、RAGAS 框架、构建评估集、常见失败模式分析 |
| 周末 | **项目：知识库问答系统** | 选取一个领域文档集，搭建完整 RAG 流水线：切分→向量化→混合检索→重排序→生成→引用标注；对比不同策略的效果差异 |

**✅ 验收标准**：能搭建完整 RAG 流水线并解释每个环节的作用；能通过评估指标定位 RAG 效果差的原因（检索问题 vs 生成问题）

## 第 5 周：多 Agent 协作系统

**目标**：掌握多 Agent 协作模式，能构建多角色协同系统

| 日期 | 主题 | 内容 |
|------|------|------|
| 周一 | 多 Agent 协作模式 | 主管-工人(Orchestrator-Worker)、辩论(Debate)、流水线(Pipeline)、群体讨论(GroupChat)；各模式的适用场景与通信开销 |
| 周二 | Agent 角色与分工设计 | 角色定义（专业能力/工具权限/输出格式）、任务分配策略、结果聚合与冲突解决、角色间信息传递协议 |
| 周三 | AutoGen 与 CrewAI | AutoGen 的 ConversableAgent、GroupChat 管理器；CrewAI 的 Agent/Task/Crew 抽象、角色化编排；两个框架的设计哲学差异 |
| 周四 | 用 LangGraph 实现多 Agent | 多 Agent 状态共享设计、Supervisor 模式实现、Agent 间消息传递、子图隔离与共享状态的权衡 |
| 周五 | 多 Agent 系统设计要点 | 避免 Agent 间死循环、对话轮次控制、成本估算与优化、单点故障与降级、何时该用多 Agent vs 单 Agent |
| 周末 | **项目：多 Agent 研究团队** | 构建 3 个 Agent：规划师（拆解任务）+ 研究员（检索资料）+ 作家（撰写报告）；规划师分配任务并审核结果，不合格则打回重做；最终输出带引用的研究报告 |

**✅ 验收标准**：能根据任务选择合适的多 Agent 模式；能用 LangGraph 或 AutoGen 实现多 Agent 协作；能控制多 Agent 的轮次和成本

## 第 6 周：评估、监控与安全

**目标**：建立 Agent 质量评估体系，掌握安全防护与可观测性

| 日期 | 主题 | 内容 |
|------|------|------|
| 周一 | Agent 评估体系 | 任务完成率、步骤效率、工具使用准确率、端到端成功率；轨迹评估(Trajectory Evaluation) vs 结果评估；构建黄金测试集 |
| 周二 | 评估工具实战 | LangSmith（追踪/评估/数据集）、Arize Phoenix（开源可观测）、自定义评估器（LLM-as-Judge）、A/B 测试框架设计 |
| 周三 | 提示注入与安全防护 | 直接注入/间接注入攻击方式、系统 Prompt 泄露防护、指令隔离与权限分离、输入过滤与输出校验、工具调用的权限沙箱 |
| 周四 | 输出安全与合规 | 敏感信息脱敏(PII)、内容安全过滤、越权操作拦截、数据隐私保护、合规要求（日志留存/审计追踪） |
| 周五 | 可观测性设计 | 结构化日志（每次 LLM 调用的输入/输出/Tool/耗时/Token）、分布式 Trace 串联、Token 用量与成本统计、错误告警规则 |
| 周末 | **项目：为 Agent 加评估与安全** | 为第 5 周的多 Agent 系统接入 LangSmith 追踪；构建 20 条测试用例的评估集并自动评分；加入提示注入防护层和输出校验；搭建基础监控看板 |

**✅ 验收标准**：能设计 Agent 评估指标并用工具自动化运行；能识别和防御常见提示注入攻击；能通过 Trace 定位 Agent 失败原因

## 第 7 周：工程化与服务部署

**目标**：将 Agent 部署为稳定可运维的线上服务

| 日期 | 主题 | 内容 |
|------|------|------|
| 周一 | 服务化架构设计 | FastAPI 后端、REST vs SSE vs WebSocket 选择、会话管理（无状态/有状态/Redis）、请求队列与并发控制 |
| 周二 | 流式响应与前端对接 | SSE 流式输出实现、打字机效果、工具调用过程的实时展示、中断与取消机制、前端状态管理 |
| 周三 | 性能与成本优化 | Prompt 缓存（语义缓存/精确缓存）、模型路由（简单任务用小模型）、批处理、上下文压缩、Token 预算控制与降级策略 |
| 周四 | 容器化与部署 | Docker 镜像构建、多阶段构建优化、环境变量与密钥管理、部署平台选择（云函数/容器服务/K8s）、CI/CD 基础 |
| 周五 | 生产环境加固 | 优雅启停、健康检查、限流与熔断、错误重试与死信队列、数据持久化、灰度发布与回滚 |
| 周末 | **项目：部署 Agent Web 服务** | 将多 Agent 研究系统封装为 FastAPI 服务，支持 SSE 流式对话、会话持久化、Token 用量统计；Docker 化并部署到可访问的环境 |

**✅ 验收标准**：能独立部署支持流式输出的 Agent 服务；能设计并发控制和降级策略；能通过日志和 Trace 排查线上问题

## 第 8 周：综合实战与方向深耕

**目标**：完成一个产品级 Agent 项目，确定后续深耕方向

| 日期 | 主题 | 内容 |
|------|------|------|
| 周一 | 方向选择与技术调研 | 三个方向选一个：①代码Agent（代码生成/审查/调试）②数据分析Agent（NL2SQL/可视化/报表）③浏览器Agent（GUI操作/网页自动化）；调研该方向的开源方案和技术难点 |
| 周二 | 系统设计与架构 | 定义核心用户场景、设计 Agent 工作流、确定工具集和数据源、绘制系统架构图、拆解开发任务列表 |
| 周三 | 核心功能开发（上） | 搭建项目骨架、实现核心 Agent 逻辑、接入必要工具、跑通最小可用版本(MVP) |
| 周四 | 核心功能开发（下） | 完善边缘情况处理、加入评估测试、优化 Prompt 和工具选择、处理性能瓶颈 |
| 周五 | 产品化打磨 | 前端界面/交互优化、错误处理与用户提示、文档编写、README 和使用示例、开源准备（License/依赖清理） |
| 周末 | 总结与复盘 | 整理 8 周学习笔记、项目开源发布、总结技术栈和踩坑经验、制定后续学习计划 |

**✅ 验收标准**：有一个可展示、可运行、有文档的完整 Agent 项目；能清晰讲解项目的架构设计和技术选型；明确后续深耕方向
